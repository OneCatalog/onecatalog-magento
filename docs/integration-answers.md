# Ответы Magento-разработчику — OneCatalog Import

Решения по вопросам из [integration-plan.md](integration-plan.md) — фиксируем ДО кода.
Платформа: **Magento 2.4.x Open Source**, стандарт **v1.2**.
Легенда: 🟢 решено · 🟡 решено с оговоркой/подтвердить у владельца магазина.

---

### 1. Хранение public_id 🟢
Своя таблица **`onecatalog_map`** (`entity_id` UNIQUE, `public_id` UNIQUE). Идемпотентность
по ней, не по `sku`. `sku` семантически = артикул (§5.2).

### 2. Набор атрибутов / характеристики 🟡
Характеристики → атрибуты товара (EAV), добавляемые в **Default attribute set**.
find-or-create атрибута по коду (slug от метки) — text для произвольных, select для
перечислимых (опции find-or-create). Группа атрибутов «OneCatalog». boolean → Yes/No.

### 3. Остаток 🟡 подтвердить
Open Source 2.4 включает **MSI**. Базово пишем через **`StockRegistryInterface`**
(совместимо, дефолтный источник), на этапе §13 — опционально `SourceItemsSaveInterface`
для конкретного источника. Подтвердить: используется ли мультисклад (MSI sources).

### 4. Скидка B2B 🟡
`promo_price` → атрибут **`special_price`** (без дат = бессрочно). Альтернатива —
Catalog Price Rule (сложнее, отложим). Базовая цена → `price`. Каталожный импорт цену не
задаёт (§5.6).

### 5. Мультисайт / MSI 🟡
Импорт в дефолтный store view; остаток — в дефолтный источник/склад. Мультисайт и
несколько источников — раскладка через событие `onecatalog_pricestock_updated` (§13.7).

### 6. Расписание §13.6 🟡
Magento cron (`crontab.xml`) — на этапе полировки/после паритета. Ручной запуск
(браузерный степпер) работает всегда.

### 7. Версия / стек 🟢
Magento **2.4.x Open Source / Mage-OS**, PHP 8.1+. Классический модуль в `app/code`
(`OneCatalog_Import`), DI/declarative schema/system.xml. Adobe Commerce B2B-фичи не
используем (ведём цену/остаток сами).

---

## Блокеры (🚫) — решения
- **EAV/DI/бойлерплейт** → принимаем как цену платформы; ядро (Units/Media/PriceStock/Api)
  переиспользуем как namespaced-сервисы.
- **sku обязателен/уникален** → при отсутствии `article` генерируем `OC-<public_id>`.
- **Индексация** → после импорта/синка предупреждаем о необходимости переиндексации
  (или триггерим reindex по затронутым сущностям на этапе полировки).
- **Служебные данные** → свои таблицы (`onecatalog_map/meta/media/b2b_staging/log`),
  не атрибуты товара (§5.1).

## Что подтвердить у владельца магазина
- Версия 2.4.x; PHP 8.1+; используется ли MSI (мультисклад) и мультисайт.
- Дефолтный attribute set и store view; единицы веса/размеров.
- Настроен ли cron (для §13.6 авто-синка).
